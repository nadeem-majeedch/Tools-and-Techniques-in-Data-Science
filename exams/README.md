# Exams

The two summative exams for the course. Question banks with embedded answer
keys (CLO, Bloom's level, and difficulty per item).

| Exam | Session | Time | Covers | CLOs |
|---|---|---|---|---|
| `midterm.md` | W8 S16 | 90 min | Weeks 1–8 (Python → EDA) | CLO-1 (+entry CLO-2) |
| `final.md` | W16 S32 | 120 min | Weeks 9–16 (ML → AI-assisted workflows) | CLO-2, CLO-3 (+reproducibility) |

## Format

Both exams follow the same six-part structure, scaled by duration:

1. **MCQ** — recall and understanding with plausible distractors.
2. **Code tracing** — predict the output of short, course-familiar code.
3. **Debugging** — identify the cause of a realistic error and fix it.
4. **Short answer** — explain concepts in 1–3 sentences.
5. **Practical coding** — write runnable code in the notebook environment
   (open-notebook per instructor policy; solution keys included).
6. **Scenario / problem-solving** — apply multiple skills to a realistic
   situation; ethics items in the final.

## Usage notes

- Every item carries `CLO`, **Bloom's level**, and **difficulty** tags;
  the spread per part is summarized in each file's marking guide.
- To produce a student paper, remove the `**Answer:**` / `**Key:**` lines
  (they are on dedicated lines for easy stripping).
- The final's ethics section aligns with `../assessment-plan.md`'s AI-use
  policy and CLO-3.
- Part V (practical) follows the assessment-plan convention: executed,
  restart-safe notebook cells with visible outputs.
- Mark totals follow the confirmed institutional scheme (Mid Exam 35,
  Final Exam 40); each paper's internal point total is scaled to its course
  marks. Confirm timing and open/closed notes against program policy.
